# Онлайн-переводчик на Docker Compose

Многокомпонентное веб-приложение из **4 контейнеров** (frontend, backend, база данных,
web-сервис переводчика), которое поднимается одной командой `docker compose up`.

Пользователь вводит текст, выбирает язык — приложение переводит его и сохраняет запись
в историю переводов в базе данных.

> Лабораторная работа по теме «Контейнеризация многокомпонентных приложений с помощью
> Docker Compose». **Вариант 18 — Онлайн-переводчик**: web-сервис переводит переданный
> текст на выбранный язык, в БД хранится история переводов.

## Что вы увидите

После запуска по адресу **http://localhost:8080** откроется веб-страница с тремя блоками:

1. **Перевод текста** — поле ввода, выбор языка и кнопка **«Перевести»**
   (обращается к отдельному web-сервису переводчика через backend).
2. **Словарь переводчика** — таблица слов и фраз, доступных для перевода, с фильтром
   по направлению и поиском.
3. **История переводов (из БД)** — список сохранённых переводов и кнопка
   **«Загрузить историю»** (читает данные из базы данных).

## Что нужно для запуска

Единственное требование — **Docker** с плагином **Docker Compose**. Отдельно ставить
Python, PostgreSQL или nginx не нужно — всё уже упаковано в контейнеры.

### Windows / macOS

1. Скачайте и установите **Docker Desktop**: https://www.docker.com/products/docker-desktop/
2. Запустите Docker Desktop и дождитесь, пока в трее значок перестанет быть серым
   (надпись «Docker Desktop is running»).

### Linux

Установите Docker Engine и плагин Compose, например для Ubuntu/Debian:

```bash
sudo apt update
sudo apt install -y docker.io docker-compose-v2
sudo usermod -aG docker $USER   # чтобы работать без sudo (нужен повторный вход)
```

### Проверка, что Docker готов

Откройте терминал (Windows: **PowerShell**; macOS/Linux: **терминал**) и выполните:

```bash
docker --version
docker compose version
```

Вы должны увидеть версии, например `Docker version 27.x` и `Docker Compose version v2.x`.
Если команда не найдена — Docker не установлен или не добавлен в `PATH`.

## Запуск (быстрый старт)

Убедитесь, что Docker Desktop запущен, затем **из корневой папки проекта** (там, где лежит
`docker-compose.yml`) выполните:

```bash
docker compose up -d --build
```

Что произойдёт:

- Docker соберёт 3 образа (frontend, backend, web-service) и скачает образ PostgreSQL;
- пока первый раз скачиваются образы (**может занять несколько минут** — это нормально);
- запустятся все 4 контейнера в фоне (флаг `-d`).

Проверьте, что все контейнеры поднялись и здоровы:

```bash
docker compose ps
```

В колонке `STATUS` у всех сервисов должно быть `Up`; у `db`, `backend` и `web-service` —
дополнительно `(healthy)`. Дождитесь этого состояния (обычно 10–30 секунд).

Теперь откройте в браузере:

**http://localhost:8080**

## Как проверить, что всё работает

1. Откройте **http://localhost:8080** — должна загрузиться страница «Онлайн-переводчик».
2. В блоке **«Перевод текста»** введите, например, `Добрый день! Спасибо за помощь`,
   выберите язык **Английский** и нажмите **«Перевести»**.
   Ожидаемый результат: `Good afternoon! Thank you for help`.
   Под результатом появится строка вида «Запись #N сохранена в БД» — значит перевод
   записан в базу данных.
3. Нажмите **«Загрузить историю»** — появится список переводов из БД (в нём уже есть
   5 начальных записей и только что добавленный перевод).
4. В блоке **«Словарь переводчика»** потренируйтесь: выберите направление в выпадающем
   списке, введите что-нибудь в поиск, кликните по строке — слово подставится в поле перевода.
5. Нажмите **«Удалить»** на любой записи истории — она пропадёт из БД.
6. (Необязательно) Остановите и снова запустите контейнеры — ранее сохранённые переводы
   останутся на месте, потому что данные БД хранятся в томе `pgdata`:

```bash
docker compose down
docker compose up -d
```

> **Важно про словарь.** Web-сервис переводчика — это локальный **эмулятор** без выхода
> в интернет: он переводит слова и фразы из своего встроенного словаря (≈190 позиций,
> направления `ru↔en`, `ru→de/fr/es`). Если слова нет в словаре, оно остаётся без
> перевода — это ожидаемое поведение, а не ошибка сборки.

## Остановка и удаление

```bash
docker compose stop        # остановить контейнеры, но не удалять их
docker compose down        # остановить и удалить контейнеры (данные БД сохранятся)
docker compose down -v     # остановить, удалить контейнеры И данные БД (том pgdata)
```

## Если что-то не работает

| Симптом | Причина и решение |
|---|---|
| `docker: command not found` / «не является внутренней командой» | Docker не установлен или не в `PATH`. Установите/запустите Docker Desktop (Windows) и перезапустите терминал. |
| `Cannot connect to the Docker daemon` | Docker Desktop ещё не запущен — запустите его и дождитесь надписи «running». |
| Порт занят: `port is already allocated` / `bind: address already in use` | Порт `8080` (или `8000`/`5001`) занят другой программой. Измените левую часть в пробросе портов в `docker-compose.yml`, например `"8081:80"`, и снова `docker compose up -d`. Тогда приложение будет на http://localhost:8081. |
| Страница `localhost:8080` не открывается | Контейнеры ещё стартуют. Подождите и проверьте `docker compose ps`; `frontend` должен быть `Up`. |
| `permission denied` при работе с Docker (Linux) | Запустите команду с `sudo` либо добавьте пользователя в группу `docker` (`sudo usermod -aG docker $USER`) и войдите заново. |
| Перевод возвращается без изменений | Слова нет во встроенном словаре эмулятора — попробуйте слово/фразу из блока «Словарь переводчика». |
| Хочу посмотреть логи | `docker compose logs -f` (или `docker compose logs -f backend`). |

## Ручная проверка через API

Backend доступен напрямую на порту **8000**. Это удобно, чтобы убедиться, что сервис жив.

Проверка готовности:

```bash
curl http://localhost:8000/api/health
# {"status": "ok", "db": "ok"}
```

Перевод текста (сохранится в БД):

```bash
curl -X POST http://localhost:8000/api/translate \
     -H "Content-Type: application/json" \
     -d '{"text": "Добрый день!", "target_lang": "en"}'
```

Для **Windows PowerShell** то же самое:

```powershell
Invoke-RestMethod -Uri "http://localhost:8000/api/health"

$body = @{ text = "Добрый день!"; target_lang = "en" } | ConvertTo-Json
Invoke-RestMethod -Uri "http://localhost:8000/api/translate" -Method Post `
  -ContentType "application/json; charset=utf-8" `
  -Body ([System.Text.Encoding]::UTF8.GetBytes($body))
```

### Эндпоинты backend

| Метод    | Эндпоинт          | Описание                                       |
|----------|-------------------|------------------------------------------------|
| `GET`    | `/api/health`     | Проверка готовности backend и БД               |
| `GET`    | `/api/languages`  | Список поддерживаемых языков (от web-сервиса)  |
| `GET`    | `/api/vocabulary` | Словарь слов и фраз, доступных для перевода    |
| `POST`   | `/api/translate`  | Перевод текста (web-сервис) + запись в БД      |
| `GET`    | `/api/history`    | История переводов из БД                        |
| `DELETE` | `/api/history`    | Очистка всей истории (или одной записи `?id=N`)|

## Архитектура

| Контейнер     | Технология                    | Порт (хост) | Назначение                                          |
|---------------|-------------------------------|-------------|-----------------------------------------------------|
| `frontend`    | HTML/CSS/JS + nginx           | `8080`      | Веб-интерфейс, проксирует `/api` на backend         |
| `backend`     | Python Flask + gunicorn       | `8000`      | REST API, работа с БД и вызов web-сервиса           |
| `db`          | PostgreSQL 16                 | —           | Хранит историю переводов, инициализация `init.sql`  |
| `web-service` | Python (микросервис-эмулятор) | `5001`      | Движок перевода текста на выбранный язык            |

Все контейнеры объединены в одну bridge-сеть `app_net`, порядок запуска задан через
`depends_on` с проверкой `healthcheck` базы данных. Данные PostgreSQL сохраняются в
именованном томе `pgdata`.

```
Браузер → frontend:8080 (nginx) → backend:8000 (Flask) → db:5432 (PostgreSQL)
                                                    ↘ web-service:5001 (переводчик)
```
